# Supplementary methods and output guide

This document describes the analysis implemented in [analysis.Rmd](analysis.Rmd) and the supplementary figures and tables that it exports. The supplied merged count matrix and precomputed CIBERSORTx estimates are the starting points of the executable workflow.

## Samples and count preparation

The RNA-sequencing data were generated by de Castro et al. from flow-sorted peripheral blood cells depleted of T and B lymphocytes. The original data are held in a [restricted-access Zenodo record](https://doi.org/10.5281/zenodo.1212754). The upstream protocol described in the research report used paired-end 75-bp NextSeq 500 sequencing, FastQC/MultiQC, Trimmomatic, STAR alignment to GRCh38, and HTSeq gene counting. These upstream steps are not rerun here.

The merged integer count matrix has 35 sample columns. Metadata match 12 patients sampled before and after sAML transformation (24 progressor samples) and five patients with first and second samples who did not progress (10 non-progressor samples). The unmatched `Amostra_18` is retained in the sample quality-control table and library-size plot but excluded from analyses requiring metadata. Non-progressor samples are descriptive comparators in heatmaps and cell-state plots; they do not enter the paired differential expression contrast or GSEA ranking.

HTSeq rows beginning with `__` are removed, and version suffixes are stripped from Ensembl IDs. An archived Ensembl table supplies gene symbols and chromosomes. Genes lacking symbols remain eligible for differential expression, whereas annotated X/Y genes are removed. The expression filter is evaluated **on the 24 progressor samples** and retains genes with at least 10 counts in at least six samples. Table S11 audits this filtering; Table S1 records sample-level gene-assigned totals.

## Paired differential expression and expression plots

DESeq2 fits the 24 progressor samples with design `~ Patient_ID + Condition` and extracts the `pos` versus `pre` contrast. Positive log2 fold changes indicate higher expression after transformation. `results()` uses `alpha = 0.10` for independent filtering. The DEG set requires Benjamini–Hochberg adjusted *P* < 0.05 **and** |log2 fold change| > 0.5. Table S2 contains all tested genes; Table S3 contains the genes meeting both thresholds. In Figure 1A, genes meeting the adjusted *P* threshold but not the magnitude threshold have a separate colour.

For heatmaps containing progressors and non-progressors, size factors and a variance-stabilising transformation (VST; `blind = FALSE`) are computed across the 34 metadata-matched samples with sampling point as the visualisation design. This does not change the paired DESeq2 fit. Heatmap rows are converted to within-gene Z scores across the 34 samples. Figure 1B selects significant genes from a predefined 79-gene module list, retains module order, and groups columns by sampling point without clustering. Table S9 records the full list and each gene's panel membership. Figure S2 displays all thresholded DEGs with mapped symbols, retaining the lowest-adjusted-*P* Ensembl row for each duplicated symbol; gene rows are clustered, whereas sample columns stay in sampling-point order. Heatmap colour encodes relative expression within a gene, not absolute counts.

Figure S1 explores sample structure using the progressor-only VST matrix. PCA uses the 500 highest-variance genes and `prcomp()` with centred, unscaled sample vectors. t-SNE uses all retained genes and `Rtsne` with perplexity 5, PCA initialisation, seed 2026, `theta = 0.5`, 1,000 iterations and one thread. Figure S3 instead plots gene-assigned counts for all original samples after the HTSeq technical rows have been removed.

## Preranked gene set enrichment


All genes with finite unadjusted DESeq2 *P* values and finite log2 fold changes can enter GSEA, regardless of DEG thresholds. Ranking uses Ensembl IDs without gene-symbol deduplication. The **main GSEA analysis uses the hybrid ranking** selected in `config.yml`. Let `L` be the post-versus-pre log2 fold change and `p` the unadjusted DESeq2 P value. For numerical stability, `q = max(p, .Machine$double.xmin)`. The score is

```math
r_{\mathrm{hybrid}}=\mathrm{sign}(L)
\begin{cases}
-\log_{10}(0.05)+|L|, & q<0.05,\\
-\log_{10}(q)+|L|, & 0.05\leq q<0.10,\\
-\log_{10}(q), & q\geq0.10.
\end{cases}
```


The first two branches meet at 0.05. The implemented score is discontinuous at 0.10 because the magnitude term is dropped. Descending ranks are analysed with `fgsea::fgseaMultilevel`, `scoreType = "std"`, `eps = 1e-10`, `nproc = 1`, and seed 2026. The workflow reads frozen **MSigDB 7.5.1** Hallmark and KEGG sets with Ensembl IDs from `inputs/reference/msigdb_7.5.1_ensembl.rds`. Set-size limits are 10–500 for Hallmark and 15–500 for KEGG. The 7.5.1 TSV files in that directory are reference tables; the RDS is the file read by GSEA.

The **confidence** and **impact** scores below are calculated only as comparison rankings for Figure S4 and Table S10; they do not supply the main GSEA results:

```math
\begin{aligned}
r_{\mathrm{confidence}} &= \mathrm{sign}(L)[-\log_{10}(q)],\\
r_{\mathrm{impact}} &= L[-\log_{10}(q)].
\end{aligned}
```


The first two branches meet at 0.05. The implemented score is discontinuous at 0.10 because the magnitude term is dropped. Descending ranks are analysed with `fgsea::fgseaMultilevel`, `scoreType = "std"`, `eps = 1e-10`, `nproc = 1`, and seed 2026. The workflow reads frozen **MSigDB 7.5.1** Hallmark and KEGG sets with Ensembl IDs from `inputs/reference/msigdb_7.5.1_ensembl.rds`. Set-size limits are 10–500 for Hallmark and 15–500 for KEGG. The 7.5.1 TSV files in that directory are reference tables; the RDS is the file read by GSEA.

Figures 1C and 1D display significant KEGG and Hallmark pathways, respectively, under the hybrid ranking (BH-adjusted *P* < 0.05). Positive normalised enrichment score (NES) indicates enrichment after transformation. Tables S4 and S5 contain **all tested pathways**, including nonsignificant sets. Table S10 gives results for all three ranking metrics; Figure S4 compares which significant pathways they share within each collection. Intersection size does not establish ranking accuracy.

## Cell-state estimates and paired comparisons

The R Markdown workflow imports the supplied CIBERSORTx export; it does not rerun deconvolution. The prior analysis report names `AML_GSE116256_Expression`, derived from the Van Galen et al. AML single-cell reference, as the signature matrix. Other job settings are not recoverable from the supplied fractions. The six reported states are Monocyte, NK, GMP, Progenitor, Malignant and Promonocyte. Fractions are checked to lie between zero and one and to sum to one per sample. GMP is displayed despite its zero estimate in every analysed sample.

Figure 2A shows stacked fractions for each of the 34 analysed samples, split into pre- and post-transformation progressors and NP first and NP second. Figure 2B shows four group means alongside individual estimates; its four-group comparison is descriptive. Table S6 supplies sample-level fractions and metadata; Table S7 gives group summaries.

Figure S5 and Table S8 compare only the **12 progressor pairs**. Each state appears in a separate panel with pre- and post-transformation samples joined by patient. For testable states, a two-sided paired Wilcoxon signed-rank test is used (`exact = FALSE`, continuity correction enabled), with Benjamini–Hochberg adjustment across testable states. GMP has no test *P* value because every paired difference is zero. No state passes adjusted *P* < 0.05 in Table S8. These deconvolution estimates provide an exploratory assessment of composition.

## Supplementary figure legends

**Figure S1A. Principal component analysis of progressor pairs.** The 12 chronic-phase and 12 post-transformation samples are projected using the 500 most variable VST genes. Each point is a sample, colour indicates sampling point, the label identifies its patient, and a line joins the patient's two samples. Axis labels give the proportions of PCA variance explained. Non-progressors are excluded.

**Figure S1B. t-SNE of progressor pairs.** The same 24 samples are embedded from all filtered VST genes with perplexity 5. Colours distinguish pre- and post-transformation samples and labels identify patients. The t-SNE axes have no percent-variance interpretation.

**Figure S2. Heatmap of annotated DEGs.** The display includes thresholded DEGs with mapped symbols, one Ensembl row per unique symbol. VST expression is standardised to a row Z score across 34 samples. Gene rows are clustered, while columns retain pre-progressor, post-progressor, NP first and NP second order. Column annotations indicate sampling point and progression status. The NP columns show these paired DEGs descriptively and are not part of the DESeq2 contrast.

**Figure S3. Gene-assigned counts by sample.** Bars give counts in millions after removal of HTSeq technical categories for all 35 original count-matrix samples. Colour denotes sampling point where metadata exist. `Amostra_18` has no matching metadata and is excluded from inferential analyses.

**Figure S4A. KEGG pathway intersections by ranking metric.** Bars count mutually exclusive combinations of KEGG pathways significant at BH-adjusted *P* < 0.05 under confidence, impact and hybrid ranks. The connected dots below each bar identify its combination of rankings.

**Figure S4B. Hallmark pathway intersections by ranking metric.** The same exclusive-combination display for MSigDB Hallmark sets. These intersections show agreement among rankings; Table S10 provides the complete pathway results behind both S4 panels.

**Figure S5. Paired cell-state estimates in progressors.** Separate panels show CIBERSORTx fractions for Monocyte, NK, GMP, Progenitor, Malignant and Promonocyte in 12 pre/post pairs. Each line connects a patient's two estimates. Labels report BH-adjusted paired Wilcoxon *P* values where testable; GMP is marked as having no variation. Non-progressors are excluded from this comparison.

## Reproducibility

`analysis.Rmd` is the executable analysis, `config.yml` records its settings, and `inputs/reference/sources.json` identifies retained reference files. Rendering the analysis writes checkpoints, plot objects, tables, figures, input checksums, installed package versions, parameter values and `sessionInfo()`. Reproduction requires authorised access to the count matrix, sample metadata and CIBERSORTx export. Package and software citations are listed in the repository README.
